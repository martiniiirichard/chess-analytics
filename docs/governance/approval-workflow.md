# Project Governance

## Approval-First Workflow

All pull requests, approvals, and changes require manual approval from Martin before execution.

This applies to:

- File edits
- Dependency installs
- Data downloads
- Branch creation
- Staging
- Commits
- Pushes
- Pull requests
- Repository settings or workflow changes

## Working Rule

Before any write action, Codex should provide:

- Intended files or artifacts affected
- Purpose of the change
- Expected outcome
- Risks, tradeoffs, or irreversible effects

Work may proceed only after explicit approval.

## Review Expectations

Before commit or PR creation, Codex should show:

- Git status
- Staged files
- Diff summary
- Proposed commit message or PR title/body

No project artifact should be committed or pushed without Martin's confirmation.
